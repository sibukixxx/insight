# Insight Lab 事業活用方針

## 結論

このリポジトリは、汎用的な「AIテキスト分析SaaS」ではなく、顧客理解を起点に改善案件を獲得するための **根拠付き診断プロダクト** として使う。

最初に売るものはソフトウェアの席数ではない。インタビュー・問い合わせ・レビューを預かり、潜在ニーズ、原文根拠、反証、改善案を短期間で返す診断サービスである。Insight Lab はその分析品質を標準化し、商談中のデモと納品レポートを生成する実行基盤になる。

## 勝ち筋

- AIがもっともらしい要約を返すことではなく、`Observation → Pattern / Trace → Insight → Evidence / Counter Evidence` を人が監査できることを差別化にする。
- ローカル実行・SQLite・納品ビルド分離を、機密性の高い顧客インタビューや問い合わせ履歴を扱う企業への導入理由にする。
- `Product Opportunity` を顧客への改善提案に、`Monetization Angle` を自社の新規サービス探索に使い分ける。
- 解析画面だけで完結させず、Markdownレポートを意思決定者への共有物、次回商談の起点にする。

## 最初の顧客とユースケース

優先対象は、顧客の声を持っているが、専任リサーチャーや分析時間が不足している組織。

1. SaaS企業のPM・CS責任者: 問い合わせ、解約理由、商談ログから改善仮説を抽出
2. 制作・コンサル会社: 顧客インタビューを根拠付き提案書へ変換
3. 新規事業担当: 案件募集文、レビュー、SNS投稿から支払い意思の兆候を探索

初期は「解約要因診断」「オンボーディング改善診断」のように入力と成果物が明確なパッケージに絞る。ドメイン非依存性は内部の強みとして維持するが、販売メッセージを汎用化しすぎない。

## 提供モデル

- 導入前: 匿名化した少量データで営業デモ
- 初回商品: データ20〜100件のスポット診断 + 根拠付きレポート + 読み解き会
- 継続商品: 月次で問い合わせ・レビューを追加し、Insightと品質指標の変化をレビュー
- 将来: 顧客環境に納品するローカル版、または運用支援付きライセンス

価格はAPI利用量ではなく、対象データ量、診断テーマ、読み解き・施策化支援の範囲で設計する。解析単体は模倣されやすく、原文確認、反証、施策への接続、人によるレビューを商品に含める。

## プロダクト優先順位

1. レポートの共有性: Markdown（実装済み）からブランド付きPDF、施策オーナー・期限の追記へ
2. 評価可能性: 実案件を匿名化したGolden Datasetと、人手評価ルーブリックを整備
3. 継続利用: 前回解析との差分、Insightの新規・継続・消失を表示
4. 現場導線: Zendesk、HubSpot、Google Drive等からの入力を、実顧客の要望が確認できた順に追加
5. エンタープライズ要件: OS Keychain、完全ローカルLLM、監査ログ

当面は、チャットUI、リアルタイム共同編集、多数の可視化、汎用ナレッジ検索を作らない。根拠付き診断から施策合意までの時間を短くする機能を優先する。

## 検証指標

- 営業デモから有償診断への転換率
- データ受領からレビュー可能なレポートまでの時間
- 人が採用したInsightの割合と、そのうち施策化された割合
- Evidence原文確認後に棄却されたInsightの割合
- 継続診断率、および次回分析までに追加されたデータ件数

モデル精度指標だけでなく、顧客がレポートを共有し、意思決定や次の依頼につなげたかを事業KPIとして扱う。
